# 针对《并行编程导论与CUDA入门》课程的分层测试题（基础→原理→实操→优化）
 
## 一、基础概念题（检验核心定义区分）
 
### 1. 串行、并发、并行三者核心区别是什么？分别举生活+计算机场景例子。
1. 串行（Sequential）
同一时刻仅执行一条任务指令，前一个任务完全结束，才启动下一个，资源独占无切换。
类比：单人排队窗口逐个办理业务。
2. 并发（Concurrent）
单核CPU通过时间片轮转快速切换多个任务，宏观看起来同时运行，微观任意时刻只有一个任务在跑，是时间复用。
类比：单人客服交替回复多个客户消息。
3. 并行（Parallel）
多硬件核心同时执行多个任务，同一时刻多个任务真正同步运算，是空间资源复用。
类比：高速收费站多个窗口同时接待车辆。

### 2. CPU定位为“全能战士”、GPU定位为“流水线工人”，二者硬件架构、设计目标、适用场景有哪些关键差异？
- CPU（全能战士）
硬件：少量高性能复杂核心，搭配大容量缓存、复杂分支预测/控制单元；
设计目标：降低单任务延迟，擅长复杂逻辑、分支判断、随机调度；
适用场景：操作系统、业务逻辑、分支多的通用程序。
- GPU（流水线工人）
硬件：海量轻量化简单计算核心（CUDA Core），控制单元极简；
设计目标：最大化整体吞吐，擅长无分支、大规模重复数值运算；
适用场景：图形渲染、科学计算、深度学习训练/推理、向量批量运算。

### 3. CUDA的四大核心编程特性是什么？分别解释含义。
1. 宿主语言C/C++：基于成熟C/C++扩展，上手门槛低；
2. 异构协同架构：程序分为Host(CPU)、Device(GPU)两部分，CPU负责调度，GPU负责并行计算；
3. SIMT单指令多线程：单条指令同步调度一整个线程束（warp）内所有线程并行执行；
4. 自动资源调度：开发者仅需指定Grid/Block线程规模，CUDA底层自动分配SM、调度线程。

## 二、硬件与映射原理题（底层理解）
 
### 1. GPU内部SM（流式多处理器）与CUDA Core是什么层级关系？SIMT单指令多线程机制如何工作？
1. 层级：GPU包含多个SM流式多处理器，每个SM内部包含数十上百个CUDA Core（计算单元）、共享内存、寄存器、线程调度器；
2. SIMT（单指令多线程）：GPU以32个线程为一组（warp线程束），同一时刻warp内所有线程执行完全相同的指令；若线程分支分裂，会串行执行不同分支，产生性能损耗。

### 2. CUDA Host(CPU)内存与Device(GPU)内存交互完整流程是什么？数据传输依靠什么通路？
1. 内存分区：Host Memory = CPU主机内存；Device Memory = GPU全局显存；
2. 传输通路：通过主板PCIe总线完成CPU与GPU数据交互；
3. 完整流程：CPU内存初始化数据 →  cudaMalloc 在GPU显存开辟空间 →  cudaMemcpy 经PCIe把数据从Host拷贝到Device → GPU核函数计算 → 计算完成后 cudaMemcpy 将结果从Device传回Host内存。

### 3. CUDA三层线程层级Grid/Block/Thread分别代表什么？一维场景下全局线程索引计算公式如何推导？
1. Grid：一次Kernel调用的整体线程网格，包含全部Block；
2. Block：线程块，Grid的划分单元，单个Block内线程可共享共享内存；
3. Thread：最小执行单元，GPU独立运算线程；
一维全局索引公式： int idx = blockIdx.x * blockDim.x + threadIdx.x （你的公式正确）。

## 三、代码实操题（工程落地）
 
### 1. CUDA  .cu  文件必须使用什么编译器？NVCC编译时如何区分Host代码与Device代码？
1. CUDA代码文件后缀 .cu ，必须使用 nvcc （NVIDIA CUDA Compiler）编译；
2. NVCC自动拆分代码：Host代码交给C/C++编译器编译，Device(GPU)代码单独编译为GPU可执行指令；
3. 修饰符区分： __global__  = GPU核函数（CPU可调用、GPU执行）； __device__  = GPU内部函数（仅GPU调用）。

### 2. Kernel核函数的标识修饰符是什么？主机端调用核函数的语法  kernel<<<grid,block>>>(args)  中两个参数分别代表什么？
1. 核函数修饰符： __global__ ；
2. 调用语法  kernel<<<gridDim, blockDim>>>(入参) ：
- gridDim：网格维度，代表总共有多少个线程块Block；
- blockDim：块维度，代表每个Block内部包含多少个线程Thread。

### 3. 完整描述向量加法CUDA程序的5个执行步骤（从CPU初始化到取回计算结果）。
1. Host(CPU)：创建数组、初始化向量数据，分配CPU内存；
2. Device(GPU)：调用 cudaMalloc ，在GPU显存开辟对应大小空间；
3. 数据拷贝： cudaMemcpyHostToDevice ，CPU数据经PCIe传输至GPU显存；
4. 并行计算：调用 __global__ 核函数，GPU海量线程完成向量加法；
5. 结果回传： cudaMemcpyDeviceToHost 将GPU计算结果拷贝回CPU内存，释放显存。
 
## 四、性能优化拔高题（核心考点）
 
### 1. 为什么少量数据时GPU向量加法速度反而慢于CPU？核心瓶颈是什么？
1. PCIe传输开销：CPU与GPU之间通过PCIe总线拷贝数据延迟很高，数据量小时，传输耗时远大于GPU计算耗时；
2. Kernel启动开销：每次调用核函数存在系统调度、线程启动固定开销，小规模计算下该开销占比极高；
二者叠加导致少量数据GPU反而比CPU串行慢。

### 2. Grid-Stride Loop优化方案解决了什么性能问题？优化逻辑是什么？
当总数据量超过单次Block可处理范围时，在线程内部加入循环，让单个线程循环处理多个数据元素，用一组Grid/Block覆盖全部数据，大幅减少Kernel调用次数，消除频繁启动核函数的固定开销。

### 3. 影响CUDA程序性能的两大关键开销分别是什么？
1. PCIe主机-设备之间的数据传输延迟；
2. Kernel核函数频繁启动的调度开销。

3. 掌握CUDA并行原理，才能理解大模型分布式训练、算子编译、推理加速等AI Infra核心底层逻辑。

### 2. 若一块GPU单Block最大线程数限制为1024，待处理向量长度10000，如何设置Grid、Block维度，并写出对应全局索引计算代码？
1. 设置每个Block容纳最大线程： blockDim.x = 1024 
2. 计算Block总数gridDim：向上取整  gridDim = (10000 + 1024 - 1) / 1024 = 10 
3. 索引代码（Grid-Stride标准写法）
int idx = blockIdx.x * blockDim.x + threadIdx.x;
for (; idx < 10000; idx += gridDim.x * blockDim.x) {
    // 向量加法计算逻辑
}
设置调用： addVec<<<10, 1024>>>(...)
